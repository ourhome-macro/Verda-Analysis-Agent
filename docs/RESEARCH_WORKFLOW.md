# Plan、Replan 与并发约束

## 初始计划

开题先识别调研对象和候选竞品；用户澄清后，模型生成品牌、维度、搜索角度及按维度检索词。研究对象优先保留，最多再选 5 个竞品。`build_contract` 固定研究截止日和窗口；计划中的相关 `search_angles` 会合入实际检索词。行业专用约束（如汽车车型和指导价口径）仍然生效。

## 质检后的修订

每个品牌×维度单元标记为 `missing`、`background_only` 或 `covered`。规则质检与模型审阅共同定位返工单元；模型只给 `rework` 而没有目标时，仅在审阅文本能唯一定位单元时自动返工。其余情况发出 `replan_stop` 并保留待复核状态。`research_planner.revise_plan` 为目标单元生成新的检索主题，并以 `PlanDelta v2/v3` 记录目标、原因和契约版本。随后补采、重分析、重建矩阵并再次审阅。

返工轮次有硬上限 2；快速、深度、专家模式的预算分别是 0、1、2。每轮最多 24 个动作，两轮合计最多 36 个动作；单动作最多抓取 4 页。Replan 不能擅自替换用户设定的品牌、维度或时效窗口；仍无近期来源时报告保留 `needs_review`。

## 出站保护

发往模型和搜索服务的请求在单凭据、供应商及当前 Python 进程三个层级获取速率令牌与并发许可；等待期间不占在途槽。默认全局 6 路/4 RPS、模型 3 路/2 RPS、博查 2 路/2 RPS。分析单元和报告章节默认每批提交 3 个。429、部分 5xx、连接失败与超时使用有限次数的指数退避；流式回复已输出内容后不重放。

调整额度请查看 `backend/.env.example` 或 `api/.env.example` 的 `OUTBOUND_*`、`LLM_*`、`SEARCH_*`、`ANALYZE_BATCH_SIZE` 和 `WRITE_BATCH_SIZE`。这些上限按进程生效，不跨 Serverless 实例。
