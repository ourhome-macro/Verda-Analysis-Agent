# 运行租约隔离、原子发布与有界返工（2026-09-30）

本文记录目标仓库 `Verda-Analysis-Agent` 的可靠性修复。此前误提交到 `VerdaAI-Investigator` 的 Agent 编排功能已沿目标仓库原有提交历史移入；本仓库继续遵守不发布 `tests/` 和本机 `doc/` 数据的约定。

## 实际链路

FastAPI 创建任务后，`task_runtime` 以 SQLite 租约启动后台运行，持久化 SSE 事件。`run_pipeline` 固定研究契约，依次完成专家指派、采集、单元分析、审计、定向返工、写作和最终审校。Task Board 管单元任务的领取与租约；ArtifactStore 管 Evidence、Claim、PlanDelta 与 Report 版本。

## 本次修复

### 整条任务的租约隔离

运行心跳只延长当前、未过期的 attempt；更新不到对应行时取消旧 worker。后台事件写入也检查 attempt、状态和租约。旧 worker 失租后即使还有已发出的模型或搜索调用在执行，也不能发布报告。结束清理仅由当前 attempt 执行，避免旧 worker 清除新 attempt 的 Trace 和性能缓冲。

### 报告原子发布

正式运行通过 `publish_report_atomic` 在同一个 SQLite `BEGIN IMMEDIATE` 事务中检查当前租约，写入报告、证据索引、Report 产物、Trace，并更新任务完成状态。中途失败会整体回滚，报告不会提前出现在列表中。直接离线调用仍使用原有保存接口；其报告和证据快照写入也采用显式事务。专家统计与订阅更新属于发布后的附加操作，失败会记录日志，不会把已发布报告重新标成失败。

### 模糊审计与跨轮预算

规则或模型意见能唯一定位品牌×维度时才自动返工。模型要求返工却无法唯一定位时，SSE 发出 `replan_stop`，报告保留 `needs_review`，提示用户明确问题或提供来源。专家模式最多两轮，每轮最多 24 个动作，**两轮合计最多 36 个动作**；第二轮优先处理首轮延期单元。单动作抓取页数上限保持 4。

## 验证与边界

本机后端 `unittest` **158 项通过**。新增故障测试覆盖旧 attempt 被替换后不得继续发事件、过期租约不得发布、报告提交中后段失败时全部回滚，以及进程在报告提交后退出时的状态恢复；5×6 图测试核对 24＋12 的跨轮预算。`backend/app/core` 与 `api/app/core` 对应模块保持一致。

后台线程中已发出的外部请求无法由 Python 任务取消强制终止；限流仍按进程生效。若需要多实例共享配额或 Serverless 跨实例恢复，还需外部队列、共享限流和持久数据库。目标仓库不发布本机测试代码，发布前仍应在受控环境运行这些测试。
