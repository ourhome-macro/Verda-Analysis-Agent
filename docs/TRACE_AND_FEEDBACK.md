# Trace、Bad Case 与反馈

## 当前可观测范围

报告保存研究契约、Plan 修订、证据快照、Claim 核验、矩阵和阶段 Trace。Trace 的 Prompt/Response 为裁剪摘要；成功搜索和网页抓取尚无逐次网络 span。因此不能仅靠 Trace 证明一条结论完整的请求级来源链，需结合报告内的证据快照和 Claim 引用。

报告页可保存人工编辑数与编辑内容，但这些记录目前不是经过审阅的事实标签。`needs_review` 表示研究或审校缺口，不等于任务执行失败；`final_audit.status=passed` 也不保证矩阵的时效覆盖达标。

## 数据回流路线

适合构造四种样本：检索/取证请求、Claim 原文支持性、品牌×维度返工、章节人工修订。每条样本需要稳定的 `task_id + attempt + plan_version + cell_id`，以及来源快照哈希、规则/模型/人工标签的来源区分。历史报告复用证据 ID，导出旧样本时必须读取报告内的证据快照；全局 `evidences` 表不是旧报告可靠的归属连接。

线上回流应先可靠写入和脱敏，再生成待审核候选。人工确认后才能进入版本化评测集；提示词、检索规则或模型更新须经离线回归与灰度验证。未经审核的用户编辑和模型自评分不能自动当作训练真值。完整设计可在原开发工作区的方案文档中继续维护；此发布仓库不包含本机研究报告、评测数据或测试代码。
