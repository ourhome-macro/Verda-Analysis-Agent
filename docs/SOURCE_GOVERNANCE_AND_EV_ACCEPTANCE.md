# 来源治理、最终审校与新能源车案例验收

> 后续可信度升级及当前示例结果见 [可信度双维度改造](../doc/可信度双维度改造.md)。下文保留第二阶段首次验收记录。

日期：2026-09-23。基于已提交的第一阶段证据消费链继续演进。本次不替换博查，不引入向量数据库。

## 实现范围

1. **来源准入**：维护审核过的品牌官网注册表，域名匹配使用完整主机名/子域边界，避免 `tesla.cn.attacker.test` 冒充官网。官网检索通过博查 `include` 限制，返回后再次过滤；跟踪实际抓取地址，搜索摘要不能充当一手正文。产品、价格要求品牌官方正文；财务要求财报或监管原文。
2. **来源血缘**：规范化跟踪参数、移动/桌面域名；按同一发布机构、明确原文链接和正文近似复制聚类。高置信不再仅按域名数，改为不同原始来源组各自支持完整 Claim。链接归因只是线索，不把转载升级为官方。
3. **动态官网**：保留表格；已审核官网的空壳页面可经 Playwright/Chromium 读取渲染正文。特斯拉订购页读取整车价、配置和金融条件；比亚迪沿当前官网车型导航读取产品页；理想读取官网及车型页。没有绕过登录或反爬挑战，也没有提交订单。
4. **证据消费修正**：产品/定价任务在存在一手正文时，避免二手软文挤占其上下文。按品牌独立提取、核验并合并，每品牌最多 8 条原子事实，最多 3 路并发；`copy_context()` 保持访客与 Trace 上下文。
5. **数字与表达**：Claim 只提取事实，禁止夹带未证实的竞争优势/因果推断。数值校验只在来源侧扩展明确货币单位转换（元/万元及区间）；不自动缩放年款和车型号。报告建议必须与事实区分。
6. **最终审校**：逐段、逐核心判断、逐亮点对照已核验 Claim；检查引用与数值。不能支撑的生成内容被移除，必要时改成带引用的已核验事实。未经字段核验的数值雷达图、份额图和结构化估算不作为审校成品发布；改为能反查 Claim/Evidence 的事实台账。
7. **任务与 SSE 解耦**：后台任务独立执行，SQLite 保存执行租约、尝试次数、事件序号和状态，SSE 只观察和回放；断线自动按序号重连。任务中断后可显式重试，最近一小时的已完成品牌采集可从事件检查点恢复；分析与审校必须重新执行。访客 Key 只留内存，重试需重新提供凭据。

## 真实联调发现并修复的问题

- 直接 HTTP 抓官网时得到空正文，原实现仍可能标成功：改为真实正文状态，并使用受限官网渲染提取。
- “价格事实 + 降维打击/竞争优势”混成一句 Claim：拆分原子事实提取与报告建议，保留核验门槛。
- 货币单位换算在 Claim 和来源两侧同时扩展会产生误拦：只扩展来源侧，覆盖价格区间。
- 多品牌共用全局 24 条输出预算，特斯拉占满额度使其他品牌缺少产品事实：改为每品牌独立提取与合并。
- 二手汇总文章因为关键词密集挤掉官网片段：对产品/定价任务应用一手材料优先的确定性准入。

## 固定评测

`backend/tests/fixtures/claim_quality_36.json` 包含 36 条固定合成样本，涉及币种、月付/年付、车辆版本、月供/整车价、CLTC/WLTP、配置、质保、历史预售价和比较方向。每组包含正确、矛盾、缺依据的 Claim。

评测标签不传入被测模型。执行：

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 tests/evaluate_claim_quality.py --live --output ../docs/claim-quality-36-results.json
```

该文件记录错误放行率、正确事实召回率、unsupported 拒绝率、伪交叉验证率、耗时与 token。它是回归基线，不能冒充真实互联网准确率或大规模统计结论；转载聚类另由确定性测试覆盖。

## 前后端验收

真实点击首页“新能源车竞争格局”，选择特斯拉、比亚迪、理想，中国大陆，产品与定价；使用现有 `.env` 的真实模型与博查 Key。数据库使用本地持久 SQLite，并非 mock 或内存测试库。

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 tests/frontend_acceptance.py
```

验收脚本要求：

- 首页 → 澄清 → 工作台 → 报告完整链路可用；
- 离开工作台后任务继续运行，返回可观察进度；
- 三个品牌各自至少有一条通过来源准入和支持性校验的产品 Claim 和定价 Claim；
- 最终发布审校通过，浏览器无 JS 页面异常；
- 报告在本地研究库可重新打开；
- 审校后的 Markdown、JSON 和页面截图输出到 `doc/`。

## 本地运行

后端：`http://127.0.0.1:8010`；前端：`http://127.0.0.1:3400`。

动态官网提取和浏览器验收的可选依赖：

```powershell
cd backend
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

本机使用服务器 `.env` 模型凭据，启动进程设置 `REQUIRE_CLIENT_API_KEYS=false`，不改写 `.env`。访客公开部署的 BYOK 模式仍需请求头凭据。

## 边界

- 来源注册表当前是审核配置，新增品牌需要维护；不会相信模型凭空声明的官网。
- 聚类是保守近似，不能完整识别所有洗稿、共同未公开源头或引文关系。
- 最终审校仍使用 LLM，不构成事实正确性证明；删除或提取式修订会记录在 `final_audit.repairs`，不悄悄放行。
- 后台执行是单机 SQLite 租约与持久事件方案，尚不是跨机器消息队列；恢复采集检查点后重新分析，不支持任意节点精确续跑。Serverless 平台仍有执行时长/进程回收限制，生产长任务应使用常驻服务。
- 数据源、时效和模型结果均可能变化，报告价格须以其采集口径理解。
