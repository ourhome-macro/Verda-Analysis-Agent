# 证据消费与论点核验改造

> 第二阶段已继续实现来源准入、来源聚类、最终报告审校和持久执行基础，见 [来源治理与新能源车验收](./SOURCE_GOVERNANCE_AND_EV_ACCEPTANCE.md)。下文保留第一阶段记录。

更新日期：2026-09-23。

## 本次范围

保留博查，不增加向量数据库，也不引入第二搜索源。先修复“搜到的证据是否进入模型、是否支持论点、补采是否刷新结论”。SEO 检测、转载来源聚类仍是后续阶段。

```text
搜索与正文抽取 → 按品牌/维度选择原文片段 → 生成 Claim
→ 独立支持性校验 → 规则/LLM 质检
→ 有缺口则定向补采 → 重新选证据、生成并校验 Claim、刷新结构化分析
→ 重新质检 → 写作与交付（通过 / 待复核草稿）
```

## 实现

### 1. 原文保存与按问题选择

- `Evidence.full_text` 保存抓取后的正文，随报告 JSON 持久化；旧报告缺少该字段时使用 `excerpt`。
- 网页提取保留表格，正文最大 48,000 字符，不再仅把前 280 字符作为分析输入。
- `evidence_context.py` 对正文做 900 字符窗口、700 字符步长切分；每个片段保留 evidence ID、来源 URL 和原文字符偏移。
- 使用英文词、中文二元词和功能/定价等维度同义词，结合 IDF 加权进行确定性排序。这是词法相关性选择，不是 embedding 或神经语义重排。
- 先按维度和品牌轮流分配，再按相关性补充；同一文档最多两段，重叠片段不重复进入上下文。
- 默认最大 28 段、18,000 字符，同时用 24,000 UTF-8 字节上限保守约束片段 token 预算。这不是精确 tokenizer 计数，也不包含外围提示词与模型输出预算。
- 每次重新选择都扫描当前候选，包括追加在末尾的证据；并不无条件优先新证据，仍按问题相关性竞争。
- 分析、结构化分析、章节写作、批注深化采用新的选择器；分析只允许引用本次真实展示的证据 ID。

### 2. Claim 支持性校验

- 新增 `claim_verifier.py`，使用独立 LLM 调用（当前配置的 aux 档位）核验，不强制另一个厂商或模型。
- 每次最多核验 4 条 Claim；分析最多 24 条 Claim，每条最多 6 个引用。
- 输出 `supported / partial / contradicted / insufficient`、理由、原文引句及对应的字符偏移。
- 核验员需检查时间、币种、计费周期、地区和比较口径，不能使用外部知识替代原文。
- 服务端验证引句必须逐字出现在模型可见片段；虚构引句、未知 ID、缺失返回、格式错误、服务失败均保持 `unverified`。
- 数字额外校验：Claim 中阿拉伯数字必须出现在支持引句中；允许千分位和小数格式归一。未显式提供计算过程的推导数值会保守降级；中文数字、单位换算和完整语义仍依赖核验模型。
- 高置信要求至少两个不同域名的证据各自支持完整结论。多个片段联合支持比较结论时，不冒充多个来源各自独立支持。
- 不再在分析失败时生成带高置信标签的概括性占位 Claim。
- 分析失败只保留安全的异常类型；不保存或显示上游异常中的 Key 等敏感内容。

### 3. 补采必须更新派生产物

- `run_pipeline()` 每轮先完成补采，再统一重新选证据、分析、核验、刷新结构化对象、规则质检和 LLM 复审。
- 只有 `collect` 信封也会触发重分析，不再依赖是否同时出现 `analyze` 信封。
- 搜索缺口查询优先，其次为官方公告、当年最新进展，避免新角度被旧列表截断。
- 未通过核验的 Claim 进入质量问题，携带品牌、字段和查询内容用于后续补采。
- 维度覆盖必须由对应且已通过语义核验的 Claim 支持，不再“有一个有效字段就视为所有维度覆盖”。
- 保留快速/深度/专家级 0/1/2 次返工上限；超限未解决标记 `quality_status=needs_review`。任务执行完成与报告质量通过是不同状态。
- 报告保存最终 `evidence_selection`；Trace 记录返工新增证据和本轮实际选中数，方便检查补采是否被消费。

### 4. 前端和写作

- SSE 新增 message kind `claims_replaced`，覆盖旧 Claim 集合；历史消息保留用于回放。
- Claim 卡片显示核验结论、理由、引句和来源跳转。
- 报告显示待复核草稿提示。旧报告缺少新字段时继续兼容。
- 正文章节只以已核验 Claim 展开，没有通过校验的对应论点则显示证据不足；写作提示携带核验引句，不再注入未核验的辅助价格/五力等数值。

```powershell

```

覆盖：尾部品牌、正文后段、六品牌分配、不同维度选段、预算约束、旧报告兼容、虚构引用、错误数字、核验服务异常、部分支持、矛盾、联合支持与独立支持区别、维度门禁、collect-only 返工、超限草稿及写作输入限制。原有访客隔离测试继续保留。

真实调用（显式启用，会消耗 `.env` 对应账户额度）：

```powershell
.\.venv\Scripts\python.exe -X utf8 tests/live_evidence_chain.py --live
```

脚本先以人工构造的定价样本检查模型能否识别正确价格、错误比较、币种错误和缺证据声明，再使用真实博查、网页抓取、分析、核验、质检及写作执行小规模集成测试。为限制成本，固定研究计划与专家名册，关闭社媒支线，最多 1 轮返工；其余模式参数仅在测试进程覆盖，不修改 `.env`。

数据库使用隔离的内存 SQLite；不向现有任务/报告库写入测试数据；不打印 Key 或原始上游异常。

## 边界

- LLM 核验有误判概率，不等于事实正确性证明，也不代替最终全文审校。
- 本次核验对象是 Claim。结构化对象、图表、舆情正文和批注重写尚未全部逐字段/逐句进行支持性核验，不能宣称整份报告已经完全防幻觉。
- 来源独立性仍按域名近似，尚未识别转载血缘。
- 选择器有字数和预算限制，正文超过 48,000 字符的部分不会被保留；极小预算无法保证所有品牌/维度均被选中。
- API 超时和重试沿用既有配置；完整任务恢复、分布式执行及全局 token 计数隔离不属于本次改造。
- `backend/app/core` 和 `api/app/core` 的本次变更需要同步，避免两种部署入口行为不同。
